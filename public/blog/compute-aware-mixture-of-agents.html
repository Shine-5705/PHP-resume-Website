Compute-Aware Mixture-of-Agents: Teaching a Multi-Agent Pipeline When to Stop

May 2026 6 min read
Research LLM Agents Test-Time Compute
Read on OpenReview →

This is joint work with S Akash, accepted as a poster to the SCALE Workshop at ICML 2026. It asks a narrow, practical question about Mixture-of-Agents (MoA): if you let the pipeline decide for itself when it has aggregated enough, does it actually save compute without losing accuracy — and does that decision hold up outside the one setting where it was tuned?

The problem

Mixture-of-Agents aggregates responses from several LLMs across a fixed number of layers, and it spends exactly the same compute on every query regardless of how easy or hard that query is. A simple arithmetic question and a genuinely ambiguous one get the same number of aggregation rounds. That is wasteful in one direction (easy queries burn tokens they didn't need) and potentially insufficient in the other (hard queries might have benefited from one more round).

The idea in one line. Add a lightweight self-consistency verifier that looks at the agents' answers after each layer and decides, per query, whether to stop aggregating or keep going — instead of running a fixed number of layers for every query.

Compute-Aware MoA

We call the result CA-MoA. After each aggregation layer, the verifier checks how much the pooled agents agree with each other. High agreement is treated as a signal that further aggregation is unlikely to change the answer, so the pipeline terminates early; low agreement keeps it going, up to the token budget. The mechanism is deliberately simple — it's a signal already implicit in the agent pool's outputs, not an additional trained model.

What we found

We tested this on GSM8K across three agent-pool configurations, and the result is genuinely mixed, which is the part I think is worth being upfront about:

  • Heterogeneous pool (Llama-3.2-3B + Qwen2.5-3B): CA-MoA reached 85.0% accuracy — tied with 4-sample self-consistency and 5 points above fixed-depth MoA-1, at 1.4× MoA-1's token spend. This is the setting where adaptive stopping earns its keep.
  • Homogeneous pool (Llama-3.2-3B × 3): fixed-depth MoA-1 already saturates the agents at 92% accuracy, so there's no headroom left for the verifier to find.
  • Mixed-capability pool (adding a smaller Gemma2-2B agent): the weaker agent actively corrupts aggregation, and CA-MoA cannot rescue that on its own.

The within-MoA gain over fixed-depth MoA-1 moves from −8, to +13.3, to +5 across those three settings, tracking how "aggregation-appropriate" the pool is. What stayed consistent across all three is that the verifier's stop/continue signal is itself informative: queries the gating policy let terminate after one layer were correct 89–100% of the time, while queries that exhausted the full budget were correct only 0–40% of the time. Even where the accuracy gain disappears, the verifier is still telling you something true about which queries the pool is going to get right.

The honest takeaway. Adaptive depth helps when the agent pool is well-matched to the task and none of the agents already saturate it. It does not fix a pool that's fundamentally mismatched (too easy, or dragged down by a weak agent). The verifier's confidence signal is useful even when the accuracy win isn't there.

We've pre-registered a follow-up at a larger, similar-capability ~7B scale with n=200 to see whether the heterogeneous-pool result holds up at bigger scale.
